# Попереднє порівняння контенту товарів

Перший етап комбінованого імпортера: у розділі ERC API є окремий блок порівняння наявної картки з Icecat. Це лише читання. Блок не передає значення до імпортера, не має кнопки застосування та не виконує записів у БД.

Серверний маршрут залишається /api/erc-catalog з діями content-status та content-preview. Сервіс винесено поза каталог api, щоб не додавати нових Vercel-функцій; ліміт поточного тарифу збережено.

Наявна картка позначається саме як наявна, а не як гарантований контент ERC: у ній можуть бути інші джерела й ручні виправлення. Основний імпорт ERC працює без змін.

## Захист

- API допускає лише авторизовані ролі owner або manager. Облікові дані перевіряються на сервері.
- Бренд і SKU беруться з наявної картки за числовим ID, а не з довільних параметрів браузера.
- Зовнішня адреса фіксована: HTTPS live.icecat.biz/api. Перенаправлення заборонені.
- Тільки власні ICECAT_API_TOKEN та ICECAT_CONTENT_TOKEN у серверному середовищі. Токени не приймаються від браузера, не потрапляють у URL, повідомлення чи журнал. Демоакаунт у робочому коді не використовується; демоконтент відхиляється.
- Точний збіг бренду та повного артикулу обов'язковий; суфікси регіональних модифікацій не видаляються.
- Ручні поля, зокрема видалені вручну характеристики, позначаються захищеними. Конфлікт не перетворюється на оновлення.
- Походження, мовна позначка й ідентифікатор характеристики показуються поруч зі значенням. Невідомі відповідності потребують перевірки.
- HTML не виконується: імена й значення екрануються. Повні описи й медіапосилання не передаються в інтерфейс; показується лише їх наявність/кількість.
- Запит обмежено одним товаром, 15 секундами та 2 МБ відповіді. Інтерфейс блокує повторні натискання й має власний таймаут. Відповідь не кешується.

Цей етап не гарантує достовірності кожного значення. Усі рядки automatic=false; автоматичного застосування немає. Точний артикул або мовна позначка UK не замінюють перевірку технічного змісту й мови значення.

## Підключення

Власник має надати власний дозволений доступ Icecat й додати ICECAT_API_TOKEN та ICECAT_CONTENT_TOKEN до серверного середовища проєкту. Не надсилати секрети в чат, не зберігати в репозиторії або браузері. Цей документ не доручає створювати нові ключі чи змінювати дозволи без окремого погодження.

Кнопка перевірки налаштувань підтверджує лише наявність параметрів, не їх працездатність або права на всі бренди. Реальна перевірка — окремий запит конкретного товару. Без власних токенів модуль залишається вимкненим.

## Межі першого етапу

Ще не реалізовано: пряме збагачення з контент-API ERC, завантаження медіафайлів у сховище, збереження погоджених полів і журнал походження записаних змін. Для цього потрібні перевірений доступ, окрема схема відповідності характеристик і захищений процес підтвердження.

Локальна QA-сторінка: tests/product-content-preview.html. Вона працює лише зі штучними даними й підміняє запити на тестові відповіді без звернень до сторонніх сервісів.

## Пакування серверної функції

Під час першої перевірки публікації журнал Vercel показав ERR_MODULE_NOT_FOUND для product-manual-overrides.js: автоматичне трасування пропустило браузерні ESM-імпорти з версіями в query string. Для api/erc-catalog.js явно включено public/**/*.js (лише вже публічні модулі, без секретів). Окремий регресійний тест перевіряє налаштування пакування та наявність усього дерева спільних залежностей. Локальні тести самі по собі не підтверджують працездатності опублікованої функції; потрібна перевірка після публікації.
