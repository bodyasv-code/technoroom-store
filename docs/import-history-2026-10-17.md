# Журнал імпорту — 17.10.2026

## Підключення

Виконати `supabase/import-history-upgrade.sql` у Supabase SQL Editor. Міграція створює лише таблиці журналу та RPC; поточні товари не змінює. Повторний запуск безпечний. Без цієї міграції імпорт зупиниться до будь-якого запису товарів або створення категорій.

## Поведінка

- XML ERC/ASBIS, доповнення Excel та ERC API використовують спільний записувач.
- `import_runs`: дата, автор (auth UUID), вибрані перемикачі, кількість позицій, завершення, помилки, кількість без змін.
- `import_changes`: товар/назва/SKU, створення/оновлення/фото, фактично змінені поля до та після запису.
- Продукт та його подія журналу записуються однією транзакцією. Помилка журналу відкочує зміну продукту.
- Блокування рядка і перевірка початкових значень захищають від паралельних змін.
- Фото записуються тією самою RPC під JWT адміністратора; наявні фото не перезаписуються. Неуспішне завантаження фото відображається як помилка запуску.
- Читання журналу лише адміністраторам. Прямий запис/редагування журналу з браузера не дозволений; RPC перевіряють автора й активний запуск.
- Сирі XML/Excel, ключі та облікові дані постачальників не зберігаються.
- У журналі доступні сторінки по 20 запусків і деталі до 1000 подій одного запуску (імпорт обмежений 100 товарами).
- Перерваний закриттям вкладки запуск залишається незавершеним; уже зафіксовані події доступні в деталях.

## Межі

Історія починається після встановлення міграції, старі запуски не відновлюються. Це журнал, не автоматичний відкат. Перед майбутнім відновленням необхідно звіряти поточні значення з записаними «після», щоб не стерти нові ручні правки. Створені категорії, бренди та фізичні файли сховища не є версіями товару й окремо не журналюються. Якщо запис фото відхилено через паралельну зміну, завантажений файл може залишитися у сховищі без прив’язки до товару.

## Перевірка

40 файлів тестів успішно; перевірка синтаксису admin.js та image API. SQL виконано без змін двічі у локальному PostgreSQL-сумісному PGlite (без мережі/ключів/продакшн-даних). Перевірено створення, оновлення, фото, відсутність змін, застарілі значення, заборонені поля, RLS, незмінність журналу, статуси помилок/часткового виконання та атомарний відкат при відмові запису історії.

Після підтвердження користувачем виконання SQL опубліковано commit `180ec92`. У живій авторизованій адмінці перевірено читання журналу та кнопку «Оновити журнал»: відображено «Запусків ще немає», без повідомлень про відсутні таблиці чи помилку доступу. Товари та ціни при перевірці не змінювалися; запис реального запуску буде перевірено під час наступного узгодженого імпорту.
