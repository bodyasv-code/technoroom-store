# Ручні правки товарів

## Підключення

Після наявного `supabase/import-history-upgrade.sql` виконати
`supabase/product-manual-overrides-upgrade.sql` у SQL Editor цього ж проєкту.
Міграція транзакційна та повторювана. Вона додає `products.manual_overrides`,
тригер обліку та оновлює функцію імпорту. Наявні значення товарів не змінює,
історичні записи не оголошує ручними. Після успішної міграції опублікувати
оновлення адмінки та перезавантажити відкриті вкладки.

## Поведінка

- Нові зміни категорії, бренду/brand_id та окремих характеристик через
  авторизовану адмінку фіксуються атомарно з товаром. Масові правки теж враховано.
- Створення товару вручну захищає введені поля. Створення/оновлення через
  `apply_product_import` ручних позначок не створює.
- Незмінені поля під час звичайного збереження не отримують нових позначок.
- Видалена характеристика зберігає позначку: імпорт не повертає її через
  відповідний псевдонім. Інші відсутні характеристики можна доповнювати.
- Перегляд імпорту показує ручне значення і відмінне значення постачальника.
  Захищена категорія не змінюється навіть з увімкненим оновленням категорій.
  Бренд наявного товару, як і раніше, не перезаписується.
- Сервер відхиляє зміну захищеної категорії/точних ключів характеристик.
  Очікуваний стан позначок входить у перевірку конкурентних змін імпорту.
- Ціни, залишки, фото та описи новим обліком не охоплено. Їхні попередні
  правила збережено. Ручні поля можна повторно редагувати в адмінці.
- Старі ручні зміни без позначок неможливо визначити достовірно. Після
  підключення відстежуються тільки нові зміни; масового зворотного заповнення немає.
- Прямі зміни під сервісним ключем або SQL Editor без `auth.uid()` не
  оголошуються ручними. Технічні позначки не додаються до публічних характеристик.

Тести: `node --test tests/product-manual-overrides.test.mjs`.
Використовується ізольована PostgreSQL/PGlite, без змін продукційних товарів.
