# Захист дат і повторного імпорту МТІ / ERC

Дата: 2026-11-23. Оновлення потребує `supabase/supplier-source-guard-upgrade.sql` після поточних міграцій постачальників, залишків і підтверджених відповідностей МТІ. Міграція змінює функції й додає приватні таблиці джерел та фактів; історичні товари, пропозиції та дати не переписуються.

Файл отримує SHA-256 за вмістом, незалежно від перейменування. Для XML з додатковим файлом цін / контенту враховано всі успішно прочитані файли та їхню роль. При заміні основного XML попередні додаткові файли й ціни очищаються; при заміні файлу цін базовий XML перечитується, щоб старі ціни відсутніх позицій не залишилися в попередньому перегляді.

Дата формування береться з назви виду `Прайс-лист-2026-11-12 23_37_04.xlsx` і показується для перевірки. Коли дати немає, її потрібно вказати. Час завантаження та дата зміни файлу на комп’ютері не підставляються. Часова зона — Europe/Kyiv незалежно від налаштувань браузера. Для прямої відповіді ERC API використовується час її отримання сервером, з відповідним поясненням в інтерфейсі.

База зберігає незмінну дату для відбитка джерела та історію фактів за постачальником і артикулом. МТІ перевіряє пропозицію в цілому; ERC окремо перевіряє ціну та залишок, включно з фактами, які вже збігаються з карткою і тому відсутні в її зміні. Старіший факт відхиляється; суперечливі значення за однаковий час також відхиляються. Уже оброблений той самий файл не перезаписує ціни/залишки й не освіжає дату. Повторне завантаження старого раніше обробленого файлу після новішого лишається пропуском, а не відновленням старих значень.

У МТІ `observed_at` нового запису відповідає даті джерела. Історія транзакції, закупівельні ціни, приховані чернетки, захист ручних правок та наявні перевірки ідентифікації залишаються. Повторні рядки показуються окремо від фактично змінених.

Якщо є пізніший історичний запис / перевірка, але його джерело ще не має підтвердженої дати, старіший файл блокується з поясненням і потребує свіжого прайсу або звірки. Історичний час імпорту не оголошується датою джерела. Старі вкладки без відомостей про джерело отримають вимогу оновити адмінку.

Приватні таблиці доступні тільки адміністраторам через RLS; клієнтам магазину ціни постачальника та відбитки джерел не відкриваються. Перевірки й запис фактів виконуються в тій самій транзакції, що й запис товару / пропозиції. Збій останнього рядка відкочує попередні зміни цієї порції.

Автоматичні перевірки охоплюють повторення файлу після перечитування каталогу, переназначення його дати, старіший прайс, конфлікт за однаковий час, свіжішу перевірку залишку, атомарне відкочування, власний склад нових чернеток, ручну ціну, невідомі історичні дати, приватність, зимовий/літній київський час та повний пакет із 325 рядків. Реальний прайс для перевірки на робочому каталозі не застосовується.
