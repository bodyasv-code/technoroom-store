# Постачальники та виключення імпорту

Підготовлено 20.10.2026. Перед публікацією нового admin.js виконайте
`supabase/product-suppliers-upgrade.sql` після міграцій журналу та ручних правок.
Без міграції новий імпортер блокується, решта каталогу продовжує працювати.

- `catalog_suppliers` — довідник постачальників (початково ERC/ASBIS), можна
  додавати інших для ручної прив’язки. Автоматичні адаптери наразі ERC/ASBIS.
- `product_suppliers` — окремі зв’язки товар–постачальник, SKU постачальника,
  останній успішний запуск та дата. Один товар може мати двох, трьох і більше.
- Джерело визначається форматом XML / ERC API, а не брендом. Excel лише
  доповнює XML, не створює окремого постачальника. Читання прев’ю нічого не записує.
- Успішний імпорт атомарно додає/оновлює зв’язок, у тому числі для незміненого
  товару. Не замінює вже наявних інших постачальників. Відсутність у файлі не
  прибирає зв’язок. Це підтверджене джерело, не гарантія актуального залишку.
- Редактор дозволяє явно зберегти один/обидва зв’язки, окремо від картки.
  У списку товарів є позначки та фільтр постачальника / «Не визначено».
- Нове видалення товару зі SKU вносить глобальне виключення. Без SKU надійно
  блокувати відновлення неможливо. Фото та замовлення ця міграція не видаляє.
- Таблиця `product_import_exclusions` не видаляється під час видалення товару.
  Імпорт блокується і в прев’ю, і на сервері. Кнопка «Дозволити імпорт» лише
  знімає заборону, не відновлює товар. Ручне створення картки не блокується.
- Старі видалення автоматично не реконструюються. SKU відсутнього товару
  може бути новим, а не видаленим. Додавайте підтверджені SKU вручну (до 100
  за раз, по одному на рядок); частково виконана операція показує кількість.
- Таблиці доступні лише адміністраторам через RLS, зміни — через перевірені RPC.
  Старий apply_product_import також підпадає під серверний тригер виключень.
- Повторне виконання старих міграцій не видаляє таблиці/тригер цього оновлення.
  Не використовуйте каскадне очищення таблиць для звичайного видалення товарів:
  TRUNCATE не запускає построкові тригери.

Перевірка: `node --test tests/product-suppliers.test.mjs`, повний набір
`node --test tests/*.test.mjs`. Жодних продакшн-товарів тестами не змінюється.
